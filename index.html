Native LLM Inference & Hardware-Co-Designed Trellis Quantization

Velri is an open-source neural-network inference stack built for models whose weights exceed GPU VRAM. One composable Khronos Slang kernel codebase compiles ahead of time (AOT) for CPU (AVX2, AVX-512 VNNI, ARM64, RISC-V 64) and Vulkan 1.3 / SPIR-V 1.6, paired with VTQ (Velri Trellis Quant, 1.5–6.0 bpw) — with zero Python, PyTorch, CUDA, LLVM, or Slang runtime dependencies.

Quick Build & Test

Requires CMake 3.21+, Ninja, Clang 18+ or GCC 14+ (C23), and build-time Khronos Slang (slangc). 

git clone https://github.com/velri-inference/velri.git
cd velri
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=clang -DVELRI_ENABLE_VULKAN=ON
cmake --build build
ctest --test-dir build --output-on-failure

Frequently Asked Questions

What languages are Velri and Velri-lib written in?

C23 and C++23 behind a public C23 API, with GPU and CPU kernels written in Khronos Slang and compiled ahead of time (slangc AOT). Velri is not written in Rust and does not require CUDA, Python, PyTorch, or a runtime compiler.

How does VTQ differ from EXL3 and GGUF?

VTQ packs weights into self-contained 64-byte-aligned 16×256 supertiles using a 256-step tail-biting Ungerboeck trellis (1,024 states, 16 subsets), Outer-DCT input rotation (16-row granularity avoiding +9% MoE padding overhead), and global Row-Fisher DP bit allocation. It beats both EXL3 and GGUF in 36/36 neutral-calibration KLD cells while quantizing 1.3–5.1× faster than EXL3.

Does VTQ need AVX-512 to decode fast on CPU?

No. VTQ's CPU codebooks are co-designed specifically for AVX2 vpshufb (-mno-avx512f) with zero runtime Galois popcounts and no vpblendvb, while using the exact same binary supertile layout as disk and GPU.

What happened to LTQ and .liqk?

LTQ and .liqk were earlier research milestones preserved in vtq-research for reproducibility. VTQ (.vtq v2) supersedes them as the active format for Velri.
